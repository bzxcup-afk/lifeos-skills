# 周计划与每日建议规则

## 周计划模式

### 触发条件
满足任一即可：
- 用户明确要求“帮我做本周计划 / 生成这周安排 / 本周怎么规划”
- 当前没有有效 `weekly_plan`
- 新的一周开始
- 最近执行明显偏离，原计划已不适用

### 版本询问
当用户请求周计划时，必须先问用户要：
- 简单版
- 详细版

用户未明确时，不要跳过确认。

## 简单版周计划

输出结构：

```text
【本周目标】
一句话说明本周最主要目标

【本周重点】
- 训练：
- 饮食：
- 补剂/药品：

【安排依据】
- 年龄/个人资料影响
- 近期状态影响
- 当前目标影响

【本周风险】
- 风险点1
- 风险点2

【调整原则】
如果状态差/有事件干扰，如何调整
```

要求：
- 简洁
- 个体化
- 明确体现依据

## 详细版周计划

输出结构：

```text
【本周目标】
一句话

【周详细安排】
周一：
- 训练：
- 饮食：
- 补剂/药品：
- 恢复：
- 备用方案：

...到周日

【安排依据】
- 年龄/资料
- 近期状态
- 当前目标
- 医疗/规则影响
```

### 每天必须包含的 6 个要素

- `daily_theme`：今日主题
- `training_detail`：训练类型和强度
- `diet_detail`：饮食策略
- `supplement_medication_detail`：补剂/药品时间点
- `recovery_detail`：恢复安排
- `fallback_plan`：备用方案

### 节奏安排原则

- 训练日：主要训练，强度适中
- 恢复日：休息、拉伸、轻活动为主
- 修正日：针对前一天问题做调整
- 灵活日：预留空间，可根据状态变化调整

## 计划生成必须考虑的信息

### Profile
必须考虑：
- `age / birth_date`
- `chronic_conditions`
- `past_major_issues`
- `health_constraints`
- `long_term_goal`
- `current_phase`

### 近期状态
重点分析：
- `fatigue_score`
- `sleep_hours`
- `weight_kg`
- `had_training`
- `state_tags`

### 事件与医疗
- `event_log` 的聚餐/出差/加班等影响可执行性
- `medical_records` 的异常决定安全边界
- 医疗建议优先级高于一般规则

### 规则触发示例
- `R002`: fatigue >= 8 -> 转恢复日
- `R003`: 连续 2 天高疲劳 -> 降负荷
- `R004`: 前一天聚餐 -> 饮食修正
- `R008`: 身体不适 -> 保护优先
- `R012`: 医疗异常 -> 保守调整

## 每日执行建议

输出结构：

```text
【今日执行建议】
- 训练：
- 饮食：
- 补剂/药品：

【状态】
一句话说明今天状态

【说明】
- 今天沿用周计划 / 临时调整
- 是否触发了规则
```

## 调整原则

当出现以下情况时，只调整当天或接下来 1-2 天，不轻易重建整周计划：
- 用户明确说没完成 / 不想做 / 状态很差
- `plan_status = 偏离`
- 出现干扰事件

允许的调整方式：
- 延后训练
- 改为轻训练
- 饮食修正
- 降低复杂度
- 优先恢复

## 禁止事项

- 不要忽略年龄、慢性病、健康限制
- 不要只根据当天对话生成整周计划
- 不要每天重新生成完整计划
- 不要编造历史数据
- 不要把详细计划写得过满
- 医疗相关必须保守处理
